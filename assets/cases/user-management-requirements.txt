BP.05.01 - Перегляд і пошук користувачів
US.05.01.01 - Переглянути список користувачів
Актор: суперадмін

User Story:

Як адміністратор, я хочу переглядати список користувачів, щоб бачити зареєстровані облікові записи та основну інформацію про них.

Цінність:

Адміністратор може контролювати користувачів, зареєстрованих у системі.

Acceptance Criteria

AC.05.01.01.01 - Відображення списку користувачів

Given адміністратор авторизований і має право переглядати користувачів

When адміністратор відкриває розділ «Користувачі»

Then система відображає список доступних користувачів.

AC.05.01.01.02 - Відображення даних користувача

Given список користувачів завантажений

When система відображає рядок користувача

Then у рядку відображаються ID, email, партнер, дата створення та інструменти керування.

AC.05.01.01.03 - Відсутність користувачів

Given у межах доступного адміністратору партнера немає користувачів

When адміністратор відкриває список користувачів

Then система відображає повідомлення про відсутність даних.

AC.05.01.01.04 - Помилка завантаження

Given система не змогла отримати список користувачів

When адміністратор відкриває сторінку

Then система повідомляє про помилку завантаження та надає можливість повторити запит.

US.05.01.02 - Знайти користувача за ID
Актор: суперадмін

User Story:

Як адміністратор, я хочу знайти користувача за його ID, щоб швидко відкрити потрібний обліковий запис.

Цінність:

Адміністратор може знайти конкретного користувача без перегляду всього списку.

Acceptance Criteria

AC.05.01.02.01 - Пошук за повним ID

Given адміністратор знаходиться на сторінці списку користувачів

When адміністратор вводить повний ID користувача в поле пошуку

Then система відображає користувача з відповідним ID.

AC.05.01.02.02 - Пошук за неіснуючим ID

Given адміністратор ввів ID, якого немає в системі

When система виконує пошук

Then список не містить записів і система відображає стан відсутності результатів.

AC.05.01.02.03 - Очищення фільтра

Given до списку застосований фільтр за ID

When адміністратор очищає поле ID

Then система повторно відображає список користувачів без цього фільтра.

AC.05.01.02.04 - Некоректне значення ID

Given поле ID приймає числове значення

When адміністратор вводить недопустимі символи

Then система не виконує некоректний пошук або повідомляє про неправильний формат.

Given список відфільтрований за email

Given адміністратор знаходиться не на першій сторінці

When він змінює кількість записів

Цінність:

Given користувач має неактивний статус

When адміністратор встановлює статус Active і зберігає профіль

Then система дозволяє користувачу використовувати обліковий запис.

AC.05.03.13.02 - Деактивація користувача

Given користувач має активний статус

When адміністратор встановлює неактивний статус і зберігає профіль

Then система обмежує подальший доступ користувача.

AC.05.03.13.03 - Збереження даних після деактивації

Given користувача деактивовано

When адміністратор переглядає його профіль

Then дані, замовлення та бонусна історія користувача залишаються доступними відповідно до прав адміністратора.

AC.05.03.13.04 - Самодеактивація

Given адміністратор редагує власний обліковий запис

When він намагається деактивувати себе

Then система забороняє операцію або вимагає додаткове підтвердження відповідно до бізнес-правил.

US.05.03.14 - Зберегти зміни профілю користувача
Актор: суперадмін

User Story:

Як адміністратор, я хочу зберегти внесені зміни, щоб оновлені дані застосувалися в системі.

Цінність:

Зміни профілю набувають чинності після підтвердження.

Acceptance Criteria

AC.05.03.14.01 - Успішне збереження

Given усі обов’язкові поля заповнені коректно

When адміністратор натискає «Зберегти»

Then система зберігає внесені зміни.

AC.05.03.14.02 - Повідомлення про успіх

Given профіль успішно оновлений

When операція завершена

Then система повідомляє адміністратору про успішне збереження.

AC.05.03.14.03 - Помилка валідації

Given одне або декілька полів містять некоректні значення

When адміністратор натискає «Зберегти»

Then система не зберігає форму та позначає поля з помилками.

AC.05.03.14.04 - Технічна помилка

Given під час збереження виникла технічна помилка

When система не змогла оновити профіль

Then адміністратор бачить повідомлення про помилку, а незбережені зміни залишаються у формі.

AC.05.03.14.05 - Перевірка актуальності

Given профіль було успішно збережено

When адміністратор повторно відкриває його

Then система відображає оновлені значення.

US.05.03.15 - Скасувати редагування профілю користувача
Актор: суперадмін

User Story:

Як адміністратор, я хочу скасувати редагування, щоб залишити попередні дані без змін.

Цінність:

Адміністратор може безпечно вийти з форми.

Acceptance Criteria

AC.05.03.15.01 - Скасування без змін

Given адміністратор не вносив змін

When він натискає «Скасувати»

Then система повертає його до попередньої сторінки.

AC.05.03.15.02 - Скасування з незбереженими змінами

Given адміністратор змінив одне або декілька полів

When він натискає «Скасувати»

Then система попереджає про незбережені зміни.

AC.05.03.15.03 - Підтвердження скасування

Given система показала попередження

When адміністратор підтверджує вихід

Then зміни не зберігаються, а система залишає форму редагування.

AC.05.03.15.04 - Продовження редагування

Given система показала попередження

When адміністратор відмовляється від виходу

Then форма залишається відкритою з усіма внесеними значеннями.

BP.05.04 - Видалення користувача
US.05.04.01 - Видалити користувача
Актор: суперадмін

User Story:

Як адміністратор, я хочу видалити користувача, щоб прибрати непотрібний або помилково створений обліковий запис.

Цінність:

У системі зберігаються лише актуальні облікові записи.

Acceptance Criteria

AC.05.04.01.01 - Доступність дії видалення

Given адміністратор має право видаляти користувачів

When він відкриває меню інструментів користувача

Then система відображає дію «Видалити».

AC.05.04.01.02 - Відсутність права на видалення

Given адміністратор не має права видаляти користувачів

When він відкриває меню інструментів

Then дія «Видалити» не відображається або є недоступною.

AC.05.04.01.03 - Успішне видалення

Given адміністратор підтвердив видалення

When система успішно виконує операцію

Then користувач більше не відображається у списку активних облікових записів.

AC.05.04.01.04 - Помилка видалення

Given система не може видалити користувача

When адміністратор підтверджує операцію

Then користувач залишається в системі, а адміністратор бачить повідомлення про помилку.

AC.05.04.01.05 - Користувач має пов’язані дані

Given користувач має замовлення, бонусні операції або інші пов’язані записи

When адміністратор намагається його видалити

Then система видаляє, деактивує або забороняє видалення відповідно до встановлених бізнес-правил.

US.05.04.02 - Підтвердити видалення користувача
Актор: суперадмін

User Story:

Як адміністратор, я хочу підтвердити видалення користувача, щоб уникнути випадкового видалення.

Цінність:

Система захищає облікові записи від ненавмисного видалення.

Acceptance Criteria

AC.05.04.02.01 - Відображення підтвердження

Given адміністратор обрав дію «Видалити»

When система обробляє дію

Then система відображає діалог підтвердження.

AC.05.04.02.02 - Дані користувача в підтвердженні

Given відкритий діалог підтвердження

When система відображає його

Then адміністратор бачить ідентифікатор або email користувача, якого буде видалено.

AC.05.04.02.03 - Підтвердження операції

Given діалог підтвердження відкритий

When адміністратор підтверджує видалення

Then система виконує операцію видалення.

AC.05.04.02.04 - Скасування операції

Given діалог підтвердження відкритий

When адміністратор натискає «Скасувати» або закриває діалог

Then користувач не видаляється.
